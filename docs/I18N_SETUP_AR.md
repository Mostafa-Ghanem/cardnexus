# نظام اللغات في CardNexus — Cloudflare

الفرع: `feature/i18n-ar-sa-en-rtl`، وهو مستقل عن Hostinger وعن نسخة `release/cloudflare-workers-preview-v3`.

## اللغات والاتجاه
- `ar-SA`: العربية الفصحى المناسبة للأعمال في السعودية — RTL (الافتراضية).
- `en`: الإنجليزية — LTR.
- `de`: الألمانية الأصلية — LTR.

المستخدم يختار اللغة من قائمة ظاهرة في جميع صفحات الموقع. يحفظ الموقع تفضيله في Cookie باسم `cn_locale` ويعيد تحميل الصفحة لتحديث اللغة والاتجاه من السيرفر. `html lang` و`dir` وميتا الصفحة تتغير على مستوى التطبيق، وليس بالاعتماد على JavaScript بعد ظهور الصفحة.

## سكربت الترجمة — داخل GitHub
```bash
npm ci
npm run i18n:extract
npm run i18n:translate
npm run i18n:apply
npm run i18n:review
npm run build
```
- `i18n:extract`: جرد النصوص الثابتة داخل صفحات ومكونات TSX، بما فيها `title/placeholder/aria-label`، وتسجيل المصدر في `messages/source.json`.
- `i18n:translate`: ترجمة النصوص التي ليس لها ترجمة إلى `messages/ar-SA.json` و`messages/en.json` عبر GitHub Models. تتطلب `GITHUB_TOKEN` بصلاحية `models:read`، ويُفضّل تشغيلها داخل Actions وليس على الجهاز المحلي.
- `i18n:apply`: تحويل النصوص JSX الثابتة إلى `<T text={"النص الأصلي"}/>` آليًا دون تعديل قيم المستخدم أو API أو مفاتيح النظام.
- `i18n:review`: تقرير بالتغطية والثغرات في `docs/I18N_COVERAGE.md`. يمكن إعادة التشغيل بدون ازدواجية.

**تنبيه مهم:** السكربت لا يقوم بترجمة `placeholder` والخصائص النصية الديناميكية تلقائيًا في وقت التشغيل؛ الجرد يسجلها لتعديلها عبر `useI18n().t(...)` بعد مراجعة بشرية. كذلك النصوص الديناميكية الصادرة من API والبريد الإلكتروني تحتاج ملفات ترجمة منفصلة، ولا يتم ترجمة أسماء المستخدمين والشركات.

## GitHub Action
افتح `Actions → Saudi Arabic and English localization` على فرع `feature/i18n-ar-sa-en-rtl`. عند تعديل السكربت أو اللغات تعمل المراجعة تلقائيًا، ويمكن أيضًا التشغيل يدويًا. يعتمد على GitHub Models المجاني ضمن حدوده المعلن؛ في حالة تجاوز الحصة يحتفظ النظام بما تمت ترجمته ويكتب قائمة بالنصوص المتبقية. لا تجعل التقرير الناقص مساويًا لإطلاق معتمد.

## مراجعة RTL
- اختبار القوائم والنافذة الجانبية والمودالات على الجوال وسطح المكتب.
- الاتجاه الصحيح للأرقام +966، الإيميل، URL ورموز الكروت (LTR حتى داخل واجهة عربية).
- فحص الوصول عبر لوحة المفاتيح وقارئ الشاشة و`aria-label`.
- التأكد من أن الطباعة وvCard وملفات QR لا تغيّر بيانات المستخدم.
- مراجعة مكونات Radix وتحريك الأسهم والقوائم عند الاتجاه RTL.
- اختبار أسماء عربية وإنجليزية مختلطة.

## منع الادعاءات والتسعير غير المعتمد
- لا تحول علامة `€` إلى `SAR` بدون اعتماد تسعير سعودي فعلي.
- لا تنشر ادعاءات تلقائية عن موقع السيرفر أو التوافق الكامل مع GDPR/نظام حماية البيانات الشخصية السعودي؛ يجب مراجعة سياسية وقانونية.
- صفحات الخصوصية والبيانات القانونية الألمانية مستثناة من الأتمتة عمدًا لحين صياغة نصوص معتمدة وفق السعودية وبالإنجليزية.
- لا تنشر نسخة عربية نهائية إذا أظهر تقرير التغطية نصوصًا ألمانية أو حقولًا غير مترجمة.

## التالي بعد اكتمال i18n
استكمال إنشاء قاعدة D1 وR2 المنفصلتين على Cloudflare وربطها بالدومين التجريبي مع اختبار صفحة التسجيل والـ Leads والبريد، دون أي تعديل على Hostinger أو موقع Aqar 1.
